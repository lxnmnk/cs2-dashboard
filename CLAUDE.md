# gaben.market — заметки для Claude

Сайт выкупа/продажи/обмена скинов CS2 + внутренние панели владельца (My Trades,
Arbitrage, Capital) + Telegram-боты. Node/Express (CommonJS), данные в JSON-файлах,
фронт — ванильный JS в `public/`. Владелец пишет по-русски/по-украински — отвечать так же.

## Сервер и деплой

- VPS `195.216.168.132`, пользователь `root`, папка `/root/cs2-dashboard`, процесс pm2 `cs2-dashboard`.
- Сервер — НЕ git-клон: код попадает туда через `scp` отдельных файлов. Деплой = скопировать
  изменённые файлы + `pm2 restart cs2-dashboard`.
  - файлы из `public/` кладутся в `/root/cs2-dashboard/public/`, из `sources/` — в `.../sources/`;
  - только статика (`public/*.js|css|html`) — рестарт не нужен, достаточно Ctrl+F5 в браузере;
  - всё, что `require`-ится сервером, — нужен рестарт.
- Если на этой машине есть SSH-ключ к серверу, деплой можно делать самому, но каждую команду,
  которая меняет сервер, показывать владельцу и ждать подтверждения. Без ключа — давать готовые команды.
- У КАЖДОЙ команды для владельца подписывать, где её запускать: «локально» или «на сервере».
  `scp`/`ssh` запускаются ЛОКАЛЬНО из папки проекта (владелец уже путал и запускал scp на сервере).
- Перед деплоем проверить, что в списке файлов нет данных (см. ниже) и что `node --check` проходит.
  Забытый файл ломает прод: однажды новый server.js уехал без нового reviews.js, и у всех
  клиентов «инвентарь закрыт». Деплоить все файлы, которые изменились с прошлого деплоя.

## Данные — никогда не заливать поверх серверных

На сервере живые данные; локальные копии старые. Не `scp`-шить и не перезаписывать:
`trades.json`, `capital.json`, `skinbuxSales.json`, `customers.json`, `customerBalances.json`,
`debts.json`, `promoCodes.json`, `pricingSettings.json`, `csfloatAutoListings.json`,
`csfloatAutoBargains.json`, `skinbuxPurchases.json`, `cryptoTopups.json`, `cryptoWithdrawals.json`, `binanceRefills.json`, `savedAddresses.json`, `sellAdvisorState.json`, `telegramArbSubscribers.json`, папку `priceHistory/` и прочие
файлы состояния. `config.json` — код (настройки), его деплоить можно.

## Секреты

- Ключи и токены — только в `.env` на сервере. Не печатать, не присылать, не коммитить,
  не просить владельца прислать (даже частично). `.env` в `.gitignore`.
- Куки/токены площадок (skin.place, skins.com) записываются скриптами (`skinplace-cookie.js`,
  `skins-auth.js`) прямо в `.env` на сервере.
- Не обходить капчи, антибот, подписи запросов, отпечатки браузера.

## Правила кода

- В репозитории не должно оставаться временных/тестовых роутов (например `/__devlogin`) —
  проверять перед коммитом.
- Маркетинг на сайте должен быть правдой: не писать «0% комиссии», «лучшая цена» и т.п.,
  если это не так в расчёте.
- Страницы в трёх языках: UA без префикса (`/ua`, `/account`, `/my-skins`), RU `/ru/…`, EN `/en/…`;
  HTML — тройками файлов (`x.html`, `x-ru.html`, `x-en.html`). Выплата на карту в гривне — только UA.
- `server.js` с CRLF-окончаниями; правки — через Edit, не через sed с многострочными шаблонами.
- Ошибки ботов не глушить полностью: шумные — сводить в одно сообщение, но не убирать из Telegram.
- Публичные роуты и файлы должны быть в `PUBLIC_PATHS` в server.js, иначе редирект на логин.
- Тестировать на заглушках (подменённый `fetch`, временные файлы в scratchpad), временные
  файлы состояния после теста удалять.

## Соседний проект: csfloat-bot

Go-бот перебития buy orders CSFloat — отдельный репозиторий `github.com/lxnmnk/csfloat-bot`.
На сервере `/root/csfloat-bot`, `docker compose -f docker-compose.yml up -d --build`.
Серверный `docker-compose.yml` отличается от репозиторного и не закоммичен — перед `git pull`
сохранить его и вернуть после. Дашборд кормит бота файлом `csfloat-bid-import.json`.
